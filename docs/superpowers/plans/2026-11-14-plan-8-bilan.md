## État

- **Vues.** Jusqu'à 9 vues, chacune avec ses cases. Seule la vue affichée est dessinée ; les cases des autres vues tournent pour garder leurs données à jour. `Ctrl+Alt+Gauche` / `Droite` passent d'une vue à l'autre en boucle, avec un glissement d'environ 300 ms et un flou de mouvement (case « Animer le passage entre les vues » dans Personnalisation). Au démarrage, l'écran reprend la dernière vue affichée, gardée par le service dans `vue-affichee.json`, à côté de `layout.json`.
- **Raccourcis du logiciel.** Les onglets d'un module passent sur `Ctrl+Alt+Haut` / `Bas`. La migration garde les raccourcis qu'Alex avait changés. Un raccourci n'agit que sur la vue affichée.
- **Fenêtre de réglage.** Onglets de vues au-dessus de l'éditeur de Disposition, avec un point vert sur la vue affichée, « + Nouvelle vue », et un menu pour renommer, dupliquer et supprimer. On réordonne les onglets en les faisant glisser, et Annuler / Rétablir marche aussi sur les vues. La case « L'écran suit la vue choisie » est cochée par défaut. Les cases peuvent recevoir un nom, avec un crayon à côté du titre et le nom du module en petit dessous, dans Disposition comme dans Modules. Avec plusieurs vues, l'onglet Modules range les cases en dossiers, un par vue.
- **Raccourcis des modules complémentaires.** Un module déclare ses raccourcis dans son manifeste (`"shortcuts"`, 10 au plus) et les reçoit par `CommunityModule.OnShortcutAsync` (**SDK 1.1.0**). Il ne voit jamais le clavier : le service écoute les touches et transmet l'action, au plus 5 fois par seconde et par module, aux seules cases de la vue affichée. L'installation propose les touches, cochées si elles sont libres. Une touche déjà prise par le logiciel, un autre module ou un autre programme de Windows arrive décochée, avec le nom de ce qui la tient. L'onglet Raccourcis les montre avec le point d'exclamation jaune. Le canal de contrôle passe au protocole 4, l'hôte des modules au protocole 1.1.
- **Exemples.** Démo reçoit « Changer de couleur » (`Ctrl+Alt+Maj+D`), Dépôt GitHub « Rafraîchir » (sans touche par défaut, avec un plancher d'une minute et un budget de 50 requêtes GitHub par heure glissante). Les deux passent en 1.1.0. Nouvelle page `docs/sdk/raccourcis.md`.

## Décisions

Chaque décision est suivie de son coût si elle est fausse. Les décisions de construction sont toutes dans le registre ; les plus importantes :

- **La vue par défaut a un identifiant fixe**, comme ses cases. Coût : renommer une constante.
- **Les raccourcis du logiciel sont toujours enregistrés**, même avec une seule vue (`Ctrl+Alt+Gauche` / `Droite` sont pris). Coût : une condition à ajouter si quelqu'un réclame ces touches.
- **Hors de Disposition, la bande d'aperçu montre l'écran** ; l'aperçu d'une vue cachée n'existe que dans Disposition. Coût : Alex voit la vue de l'écran dans les autres onglets.
- **La liste des cibles d'un raccourci couvre toutes les vues**, avec « — <nom de la vue> » quand il y en a plusieurs. Coût : un format de libellé.
- **Le modèle `dotnet new ashboard-module` garde `"sdk": "1.0"`** : un module sans raccourci reste installable sur la 1.1.0. Coût : une ligne du modèle.
- **Le service jette un raccourci que le module n'a pas déclaré** (défense en profondeur : les liaisons peuvent être modifiées à la main). Coût : une vérification à retirer.
- **Service injoignable à l'installation** : la touche proposée arrive cochée, sans vérification ; si Windows la refuse ensuite, l'onglet Raccourcis le montre. **Une touche prise par un autre programme reste cochable** (on peut la libérer ailleurs) ; une touche prise par le logiciel lui-même ne l'est pas. Coût : une condition.
- **« Rafraîchir » de Dépôt GitHub** : plancher d'une minute au lieu de cinq, et budget de 50 requêtes par heure glissante. Coût : quelques lignes d'un exemple.
- **Relecture finale** : corrigées tout de suite, M1 (les cases complémentaires de la vue affichée sont annoncées cachées tant qu'il n'y a ni écran ni aperçu), M2 (la migration tolère des touches nulles), M3 et M4 (documentation : file de 8 raccourcis, limite de 160 caractères, budget GitHub honnête) et M5 (copier une vue ne coupe plus un emoji en deux).
- **Démo et Dépôt GitHub passent en 1.1.0** pendant la tâche 14 : installer Démo devient une vraie mise à jour, ce qui vérifie que seules les nouvelles actions sont proposées. Coût : un numéro.
- **Le crayon renomme aussi depuis l'onglet Modules**, dans le même historique Annuler / Rétablir que Disposition. Coût : retirer un bouton.
- **Noms des champs du manifeste** : `shortcuts`, `keys` (et `id`, `name`) au lieu de `actions` et `shortcut` dans la conception (§ 5.5). Le mot « raccourci » est celui de la fenêtre et de la documentation. Coût : nul tant que le SDK 1.1.0 n'a pas de modules publiés par d'autres ; ensuite, garder ces noms.

## Petits points repoussés (sans urgence)

Le détail est dans le registre de construction (`.superpowers/sdd/2026-11-11-plan-8-vues-et-raccourcis/`, ignoré par git) ; les plus utiles :

- **Service** : `DisplayLoop.cs` dépasse 1 500 lignes, et la machine du glissement pourrait devenir sa propre classe. La première image d'un glissement reste soumise au plafond d'images par seconde (jusqu'à 83 ms d'attente à 12 images/s). Quelques calculs de vue voisine se font hors du verrou (course théorique sous des appuis simultanés). `DisplayedViewStore` perd une écriture si le disque échoue un instant, sans réessayer.
- **Canal de contrôle** : se réabonner à la même vue cachée l'annonce cachée puis visible (bref clignotement possible des cases complémentaires ; la fenêtre ne le fait jamais). L'aperçu d'une vue cachée alloue une fermeture à chaque image.
- **Hôte** : l'avertissement d'un raccourci abandonné n'arrive qu'après la fin de l'appel au module ; un module bloqué l'abandonne donc en silence.
- **Fichiers de disposition** : au-delà de 9 vues, les cases des vues en trop sont perdues avec un avertissement (l'étagère serait plus sûre) ; `LayoutJson.cs` gagnerait à sortir la lecture des vues dans son propre fichier.
- **Fenêtre** : le premier choix d'action de l'onglet Raccourcis est choisi par sa position ; une commande future sans libellé montrerait son nom anglais ; la barre d'onglets de vues n'a pas de test de glissement à la souris (seulement le déplacement lui-même).
- **Documentation** : l'aide du jeton GitHub dit « jusqu'à 50 » requêtes par heure, alors que le pire cas dépasse brièvement 60.
